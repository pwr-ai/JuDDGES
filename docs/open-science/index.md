# JuDDGES — Data Gathering, Model Training and Annotation (PL)

Software-sustainability and reproducibility report for the JuDDGES codebase, structured as direct answers to standard open-science evaluation criteria (FAIR4RS / EOSC software-sustainability).

Repository: <https://github.com/pwr-ai/JuDDGES>
Last verified against the repository: **2026-04-30**.

## 1. Project context and purpose

| Aspect | Description |
|---|---|
| **Briefly describe the context and purpose** | The **JuDDGES** repository provides an end-to-end codebase for working with Polish (and to a lesser extent English) legal-judgment data. It covers six tightly integrated capabilities. (1) **Data acquisition** from the Polish Common Courts API and the National Administrative Court (NSA), implemented under [`scripts/nsa/`](https://github.com/pwr-ai/JuDDGES/tree/master/scripts/nsa) and the data loaders in [`juddges/data/`](https://github.com/pwr-ai/JuDDGES/tree/master/juddges/data). (2) **Storage and semantic retrieval** of judgments in a Weaviate vector database, with predefined collections (`legal_documents`, `document_chunks`), an ingestion pipeline ([`scripts/embed/ingest_to_weaviate.py`](https://github.com/pwr-ai/JuDDGES/tree/master/scripts/embed)), and a Docker-Compose deployment in [`weaviate/`](https://github.com/pwr-ai/JuDDGES/tree/master/weaviate). (3) **Automated dataset analysis** producing descriptive statistics and quality reports, organised under [`scripts/analytics/`](https://github.com/pwr-ai/JuDDGES/tree/master/scripts/analytics) and accompanying notebooks in [`nbs/`](https://github.com/pwr-ai/JuDDGES/tree/master/nbs), so every published dataset ships with a transparent statistical profile. (4) **Schema-driven information extraction** that runs LLM inference over the collected corpus according to a user-defined Pydantic schema ([`juddges/models/`](https://github.com/pwr-ai/JuDDGES/tree/master/juddges/models), [`scripts/extraction/`](https://github.com/pwr-ai/JuDDGES/tree/master/scripts/extraction)), supporting both local vLLM and OpenAI-compatible API back-ends. (5) **Fine-tuning and evaluation** of Large Language Models — Llama 3.1/3.2, Mistral, Bielik (Polish), Phi-4 — using PEFT/LoRA via Unsloth ([`scripts/sft/`](https://github.com/pwr-ai/JuDDGES/tree/master/scripts/sft)), evaluated with both n-gram metrics and an LLM-as-judge protocol ([`juddges/evaluation/`](https://github.com/pwr-ai/JuDDGES/tree/master/juddges/evaluation)). (6) A **Human-in-the-Loop (HITL) annotation toolkit** built on Label Studio in [`label_studio_toolkit/`](https://github.com/pwr-ai/JuDDGES/tree/master/label_studio_toolkit): annotation tasks are declared as Pydantic schemas + form templates, and the toolkit automates LLM preannotation, task and prediction upload, human review and correction, and export of the corrected annotations as a structured dataset (`dataset.json` + `schema.yaml`). Three reference annotation tasks are bundled — Swiss Franc loan cases ([`schemas/swiss_frank.py`](https://github.com/pwr-ai/JuDDGES/blob/master/label_studio_toolkit/schemas/swiss_frank.py) + [`form_templates/swiss_frank.xml`](https://github.com/pwr-ai/JuDDGES/blob/master/label_studio_toolkit/form_templates/swiss_frank.xml)), personal rights ([`schemas/personal_rights.py`](https://github.com/pwr-ai/JuDDGES/blob/master/label_studio_toolkit/schemas/personal_rights.py) + [`form_templates/personal_rights.xml`](https://github.com/pwr-ai/JuDDGES/blob/master/label_studio_toolkit/form_templates/personal_rights.xml)), and English appeal-court appeals ([`schemas/en_appealcourt.py`](https://github.com/pwr-ai/JuDDGES/blob/master/label_studio_toolkit/schemas/en_appealcourt.py), driven by the [`configs/annotate_data_en_appealcourt.yaml`](https://github.com/pwr-ai/JuDDGES/blob/master/configs/annotate_data_en_appealcourt.yaml) Hydra config) — to serve as runnable templates for new annotation projects. The repository was created so the JuDDGES project can publish high-quality, well-documented Polish-language legal datasets and reproducible model artefacts on the [JuDDGES Hugging Face organisation](https://huggingface.co/JuDDGES). It can be reused by anyone wishing to reproduce the data-collection workflow, refresh the datasets with newly published judgments, extract structured information under a custom schema, or fine-tune an LLM for a domain-specific extraction task. |

| **INTEROPERABILITY — Standard I/O formats** | Do you use existing and standard input/output formats? | Yes. All data exchange relies on widely adopted, well-specified formats so the artefacts can be consumed by third-party tools without bespoke adapters. Datasets are stored as **Parquet** and distributed via the **Hugging Face `datasets`** library, with **CSV** and **JSON** used for tabular and metadata exports (sample CSVs are under [`data/sample_data/`](https://github.com/pwr-ai/JuDDGES/tree/master/data/sample_data)). | **REPRODUCIBILITY — Releases** | Do you provide releases of your software? | Yes. The repository publishes versioned **Git tags** on GitHub — the current research-reproducibility tag is [`neurips_v0.1`](https://github.com/pwr-ai/JuDDGES/tree/neurips_v0.1), which captures the codebase state used to reproduce the SFT experiments on the `pl-swiss-franc-loans` dataset — allowing third parties to pin to a specific snapshot of the codebase. The lockfile [`dvc.lock`](https://github.com/pwr-ai/JuDDGES/blob/master/dvc.lock) records the exact inputs, parameters, hashes, and outputs of every executed run, so a third party can reproduce any reported artefact end-to-end with `dvc repro <stage>`. Sample data committed under [`data/sample_data/`](https://github.com/pwr-ai/JuDDGES/tree/master/data/sample_data) is itself version-tracked through DVC `.dvc` pointer files. |
